# Silent Data Loss Prevention Design

## Scope

Strengthen the supported corpus export path so duplicate or missing clips cannot be
hidden by aggregate row counts and two planned clips cannot silently overwrite the
same output files. The change covers `export-corpus`, `export-aligned-map`, and the
final manifest verifier. It does not change alignment scoring or decide which
segments count as matched.

## Invariants

Before export writes a clip, every planned segment must have:

- a unique SRT index within its source chunk;
- a unique deterministic clip ID within its output directory;
- unique audio, normalized-text, and original-text output paths.

The full export tree is preflighted before the first ffmpeg invocation or text-file
write. A validation failure therefore cannot leave a newly exported prefix followed
by missing later chunks.

Existing outputs may be reused during a deterministic rerun only when their caption
contents agree with the planned normalized and original text. An existing caption
with different content is a conflict and aborts the export before any writes. Audio
is regenerated by the normal ffmpeg command after preflight because the current
manifest does not retain enough source-audio provenance to prove an existing clip is
identical. This design does not delete stale files that are outside the new manifest.

## Export Design

Introduce a small internal export-plan representation in `alignment.export`. A plan
contains the source segment, deterministic paths, normalized and original text, and
ffmpeg command. Planning is pure and performs no filesystem writes.

Validation runs over all plans selected by an export command. It reports duplicate
SRT indices, clip IDs, or output paths with enough chunk/index context to locate the
source. It also checks existing caption files for conflicts. Only after every plan
passes does execution create directories, run ffmpeg, write captions, copy speaker
maps, and write the manifest.

Paired original/clean SRT export additionally requires a one-to-one index contract:
both SRT files must have unique indices and exactly the same index set. This prevents
a dictionary conversion from silently dropping duplicate clean rows or silently
falling back when a clean row is absent.

## Manifest Verification

The verifier always checks uniqueness of non-empty `clip_id`, `audio_path`,
`text_path`, and `text_original_path` fields. Duplicate values are reported even when
the total manifest row count matches the expected aggregate.

With `--check-speaker-maps`, verification derives each manifest row's chunk from the
directory containing its audio file and derives its SRT index from `clip_id`. For each
exported chunk it compares the manifest index set with the speaker-map rows eligible
for export:

- all speaker-map indices for a normal export;
- matched speaker-map indices when verification is told the export was
  `--matched-only`.

Missing expected indices and unexpected manifest indices are separate failures.
Duplicate indices in either the manifest chunk or speaker map are failures rather
than being collapsed into dictionaries. Because the verifier cannot infer whether a
manifest was produced with `--matched-only`, add an explicit verifier flag with the
same name and document that it must mirror the export invocation.

Aggregate expected-row checks remain as a useful summary but are no longer the sole
completeness proof.

## Errors and Compatibility

Validation errors use `ValueError` in the Python API and surface as non-zero CLI
failures. Messages include representative conflicting IDs or paths. Existing valid
commands keep their current arguments and behavior. The verifier gains only the
optional `--matched-only` interpretation flag.

The export is preflight-safe for validation failures. It is not fully transactional
against ffmpeg or disk failures during execution; successfully written earlier clips
remain available for diagnosis and a deterministic rerun.

## Tests

Add focused regression tests that first demonstrate each current failure:

- paired SRT files with missing, unexpected, or duplicate indices;
- duplicate SRT indices and sanitized filename collisions before any subprocess or
  caption write;
- a later invalid chunk causing whole-tree preflight failure without partial output;
- conflicting existing captions rejected before writes;
- identical captions accepted on deterministic rerun;
- duplicate manifest IDs and each duplicate path field;
- a balanced missing/extra index set whose aggregate row count still matches;
- duplicate speaker-map and per-chunk manifest indices;
- correct reconciliation for complete and matched-only exports.

Run the focused tests after each test-driven change, then the repository gates:
`pytest`, `ruff check .`, and `ruff format --check .`.
